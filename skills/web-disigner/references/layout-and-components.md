# Вёрстка и компоненты

## Адаптивная композиция

Использовать CSS Grid и Flexbox по структуре контента, ограниченные контейнеры и fluid-размеры с `clamp()`, когда они сохраняют шкалу. Выбирать breakpoints по моменту разрушения композиции, а не только по именам устройств. Проверять 390, 768 и 1440 CSS-пикселей и промежуточную ширину, если есть сложная сетка.

Проверять длинные русские слова, имена, числа, подзаголовки и кнопки. Использовать `min-width: 0` там, где flex/grid-дети должны сжиматься. Не лечить горизонтальное переполнение глобальным `overflow-x: hidden`, пока не найдена причина. Отличать намеренную карусель от сломанной страницы.

Задавать изображениям размеры или aspect-ratio; выбирать осмысленный `object-position` для телефона. Не делать главный LCP-кадр лениво загружаемым. Загружать тяжёлые галереи и видео по необходимости. Сохранять статическое содержимое при отключённой анимации.

Использовать семантические landmark-элементы, последовательные заголовки и ссылки с понятными названиями. Задавать текстовый контраст, видимый фокус и достаточную область нажатия. Проверять шрифты на реальных русских строках и в доступных начертаниях.

## Использование компонентов

В существующем проекте сначала находить готовые компоненты и design tokens. Для React выбирать shadcn/ui для доступных базовых взаимодействий, если он подходит стеку. Проверять `components.json`, базовую библиотеку, aliases и текущую версию Tailwind. Не переносить API Base UI в Radix и наоборот.

Читать `upstream/shadcn/guide.md` и нужные rules как контекст библиотеки, сохраняя выбранную визуальную систему. Не навязывать компонентную библиотеку статической странице. Не устанавливать все компоненты ради одного меню. Перед обновлением изучать diff и сохранять локальные изменения.

Для React Bits смотреть сначала `upstream/react-bits/overview.md`. В `../assets/react-bits/` сохранены TypeScript/Tailwind-примеры BlurText, SplitText, ScrollReveal, TiltedCard и Masonry. Они требуют проверки зависимостей и адаптации под проект; не считать их готовым приложением. Для других компонентов использовать pinned-источник из `sources.md`.

Для архитектуры React читать `upstream/vercel/composition-patterns.md`. При фактических проблемах производительности искать нужный раздел `react-best-practices.md`: waterfall, bundle, re-render или rendering. Не превращать простой лендинг в сложную систему состояния.
