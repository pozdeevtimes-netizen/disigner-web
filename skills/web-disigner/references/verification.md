# Проверка готового сайта

## Доказательства

Проверять фактический рендер и работающие действия. Дизайнерское намерение, успешная компиляция и снимок HTML не подтверждают качество визуальной композиции. Использовать доступный браузерный инструмент или Playwright; не обходить ограничения инструментов.

Проверить основной путь посетителя, мобильное меню, ссылки, формы, галерею и диалоги. Проверить Tab/Shift+Tab, Enter и Escape по применимому сценарию. Проверить возврат фокуса и отсутствие скрытых интерактивных элементов в закрытом меню.

Осмотреть снимки 1440×900, 768×1024 и 390×844; ширины — исходный набор, дополнить по проблемам. Проверить реальный текст, изображение первого экрана, липкую шапку, переполнение, кадрирование и плотность. Проверить reduced-motion и 200% zoom вручную. При необходимости проверить Safari/WebKit и целевое устройство.

## Помощник Playwright

Из корня проекта, где установлен Playwright, выполнить:

```bash
node <skill-dir>/scripts/inspect-site.mjs http://127.0.0.1:3000 --out /tmp/web-disigner-review
```

Скрипт открывает три viewport, сохраняет PNG и JSON, проверяет runtime-ошибки, неудачные ресурсы, изображения и подозрительное переполнение. Дополнительно открывает мобильную страницу с reduced-motion. Он не отправляет формы и не нажимает произвольные кнопки. После выполнения обязательно открыть и оценить скриншоты, затем вручную проверить целевой сценарий.

При необходимости указать `--module /absolute/project/node_modules/playwright` или `--browser webkit`. При отсутствии Node, Playwright или браузерного бинарника использовать доступный browser tool и сообщить конкретное ограничение. Не считать `--help` полноценной проверкой сайта.

Автоматический отчёт не доказывает контраст, доступность, корректность UX или визуальное качество. Проверять эти свойства отдельно. Считать long-page screenshots внутренними рабочими материалами; не сохранять их как пользовательский deliverable без запроса.

## Завершение

После первой общей проверки исправить подтверждённые проблемы пакетно и повторить затронутые проверки. Если остаётся существенная неисправность, продолжить её исправление; не ограничивать количество попыток, когда результат ещё не отвечает брифу. Если новых дефектов нет, закончить работу.

Для подробностей читать `upstream/playwright/screenshots.md`, `visual-comparisons.md`, `emulation.md` и `configuration.md` по необходимости. Формальный accessibility-audit и пользовательское исследование не заменять скриншотами.
