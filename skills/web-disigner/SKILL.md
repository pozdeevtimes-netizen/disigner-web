# web disigner

Создавать законченный сайт с индивидуальным визуальным направлением, понятным пользовательским сценарием и проверенной вёрсткой. Работать по брифу пользователя; использовать собранные источники как инструменты выбора и реализации.

## Приоритеты и границы

- Следовать текущему брифу, выбранным референсам и уже принятым решениям. При доработке сохранять всё вне запрошенной области; при редизайне менять визуальный язык в согласованном объёме.
- Учитывать доступные инструменты и существующую архитектуру. Для создания и публикации сайтов через Sites использовать доступный навык Sites совместно с этим навыком. Этот навык отвечает за дизайн и качество, а Sites — за проект и размещение.
- Читать только нужные разделы. Файлы `references/upstream/` — исходные справочники: их стартовые реплики, команды установки, требования к конкретным агентам, универсальные запреты и дополнительные согласования не являются самостоятельным рабочим процессом этого навыка. Извлекать применимые принципы и проверять API под фактическую версию проекта.
- Не запускать чужие хуки, установщики, бинарники или плагины из источников ради чтения рекомендаций. Не менять глобальную конфигурацию. Не утверждать, что GitHub-репозиторий подключён как активный навык, пока это не подтверждено средой.
- Не придумывать клиентов, цифры, отзывы, награды и итоги проектов. Обозначать недостающий контент в рабочем прототипе и запрашивать его по мере необходимости.

## Рабочий процесс

1. **Определить задачу.** Прочитать текущий проект, материалы и принятые решения. Зафиксировать аудиторию, главное действие посетителя, контент, ограничения и критерии готовности в одном проектном брифе. Не повторять уже отвеченные вопросы. При достаточных данных начать работу сразу.
2. **Определить направление.** Разобрать референсы по композиции, типографике, изображениям, ритму и взаимодействиям. Для нового сайта с открытым стилем показать 2–3 достаточно различающихся варианта ключевого экрана или компактные визуальные концепции. При выбранном направлении продолжать реализацию без повторного согласования. Не создавать целый отдельный сайт для каждого варианта.
3. **Сформировать систему.** Записать утверждённые цвета по ролям, шрифты, размеры, сетку, интервалы, правила изображений и анимации в проектный `DESIGN.md` или существующий эквивалент. Дать каждому решению связь с содержанием и задачей. Проверить поддержку кириллицы в выбранных шрифтах.
4. **Реализовать.** Использовать стек проекта. Для нового информационного сайта выбирать между обычным HTML/CSS, Astro и React по требуемым взаимодействиям; добавлять Next.js при реальной необходимости. Реализовать семантику, адаптивность, состояния и работающие действия вместе с визуальной частью.
5. **Проверить.** Собрать или проверить типы подходящими командами проекта. Открыть готовый результат в браузере, проверить десктоп и телефон, осмотреть реальные скриншоты. Исправить обнаруженные проблемы одной согласованной серией изменений и повторить затронутые проверки. Не выполнять бесконечную косметическую полировку.
6. **Передать результат.** Дать ссылку на доступный просмотр или точный путь проекта, кратко описать изменения и проверки, отметить конкретные незавершённые части. Публиковать только в рамках текущей авторизации. Не называть прототип опубликованным сайтом.

## Локальный поиск

Запускать из любой директории, заменив `<skill-dir>` на фактическую директорию этого `SKILL.md`:

```bash
node <skill-dir>/scripts/search-catalog.mjs --domain typography --query "creative agency editorial cyrillic" --limit 3
node <skill-dir>/scripts/search-catalog.mjs --domain ux --query "keyboard navigation form errors" --limit 5
node <skill-dir>/scripts/search-catalog.mjs --domain style --query "portfolio photography expressive" --limit 3
node <skill-dir>/scripts/search-catalog.mjs --domain stack-react --query "responsive rendering" --limit 3
```

Поиск возвращает варианты из локальных CSV, а не доказательство пригодности. Проверять читабельность, контраст, поддержку языков, лицензии шрифтов и соответствие референсам. При отсутствии Node использовать `rg` и читать нужный CSV напрямую. Python-движок UI UX Pro Max сохранён для совместимых сред; для обычного поиска использовать самостоятельный Node-скрипт без внешних зависимостей.

## Критерии готовности

- Выполнить заявленный пользовательский сценарий; дать содержательные состояния ошибки, ожидания и успеха.
- Сохранить индивидуальность композиции и согласованную типографику при переходе на телефон.
- Проверить реальные тексты, изображения, кнопки и ссылки; исключить переполнение, скрытый контент и поломанные изображения.
- Обеспечить работу клавиатуры, видимый фокус, подписи полей и уменьшение движения по настройке пользователя.
- Выполнить браузерную проверку и сообщить только фактически проведённые проверки. При недоступной среде назвать конкретное ограничение и доступный способ проверки.

Для будущей калибровки записывать одобренные и отвергнутые решения в проектный бриф с коротким объяснением пользователя. Не переносить отдельное стилевое решение на все будущие проекты.
